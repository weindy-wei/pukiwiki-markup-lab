# FilmWiki Step 23: Tabler read-only production workspace v0.1

This is a standalone, **read-only** and **local-first** UI. It is not yet a Wiki plugin or a production data editor. It consumes the **version 1 `filmwiki-portable-export` JSON** generated by `tools/table_import/export_store.py`.

## Running locally

- Run `bash web/filmwiki/bootstrap-tabler.sh` once to self-host the pinned `@tabler/core@1.6.1` MIT CSS and JS assets. This requires network only during build; the app has **no runtime external requests**.
- From the repository root run `python3 -m http.server 8089 --bind 127.0.0.1 --directory web/filmwiki` and open `http://127.0.0.1:8089/`.
- Click **导入 JSON** to select a local export, or explore the clearly labeled synthetic demonstration data already on the screen.
- Run `node --test tests/filmwiki_ui.test.mjs` for the pure model tests.

## Three views

- **Grid:** full-text search across all original cells, status selection when a real status field exists, page size 50, user-selectable display columns (1–8 maximum), original worksheet row number and per-record identity.
- **Thumbnail:** page size 24, film-style cards. Missing or unresolved image references never turn into speculative thumbnails. The placeholder is explicit.
- **Detail:** all original fields, multiline values, explicit null values, parent-link status and candidates, unresolved image filenames. Next/previous navigation.
- **Navigation:** worksheet list supports empty schema-only tables. Original 17+ columns are never truncated in the underlying JSON or in Detail.
- **Import:** the user selects a `filmwiki-portable-export` JSON file; it is parsed **in browser memory only**. No cookies, IndexedDB, localStorage, telemetry or API requests. The Content Security Policy has `connect-src 'none'`. No user data is embedded in source code.

## Why not use live SQLite in browser?

The Stage 22 SQLite canonical data store is a private storage layer, not an unauthenticated HTTP resource. This first UI deliberately loads an **explicitly exported JSON file** instead of serving sensitive SQLite data through the public PukiWiki site. An authorized, read-only API with access checks can be added later.

## Privacy and deployment boundaries

- **Never copy real employer/client data to this public GitHub source repository.** Synthetic demo only.
- No PukiWiki core edits, theme replacement or database writes.
- `web/filmwiki/vendor` is ignored by Git. Tabler source and license are retained on the machine after installation.
- Run on loopback or an access-controlled private endpoint; do not expose the PukiWiki PHP 8.1 test stack on the internet.
- Rendering uses DOM `textContent` rather than HTML interpolation of imported fields, preventing untrusted cell text becoming page markup.
- Large JSON import (>20 MiB) is refused in the browser. Render pagination is 50 rows for Grid, 24 for Thumbnail, and one detail at a time. App-level data limits are bounded.
- No attachment or media file reads. A filename such as `image.png` remains an unresolved reference, not a trustworthy image identity.
